## 2026-09-06T22:30:00Z — Nightly rolling secret scan: findings reach the step summary and an artifact (Claude Code)

- **Agent/tool:** Claude Code
- **Repos:** dizhaky/.github
- **Correction to my own earlier claim, first.** PR #23 and obsidian-vault#377 both listed `reusable-nightly-maintenance.yml` as a follow-up carrying "the same class of defect" as the workflows they fix. **That was overstated.** Verified against gitleaks 8.24.3: `--verbose` already prints `File`, `Line`, `RuleID`, `Commit`, `Author`, `Date` and `Fingerprint` — all redacted — to the job log. This scan was never blind. The other two were (no `--verbose`, no `--report-path`), which is why they emitted only `leaks found: N`.
- **What was actually missing, and what this changes:** the step wrote a `## Secret scan (rolling 2-day window)` header plus the `Since:` line to `$GITHUB_STEP_SUMMARY` and then sent every finding to the raw job log only. For a nightly job fanned across many repos, the summary is the scannable surface. Now the scan also writes a redacted JSON report, findings render under that existing header as `file:line rule=… commit=…`, and the report uploads as an artifact.
- **Scope:** `--redact`, `--verbose`, the rolling 2-day `--log-opts` window, the trigger surface and `--exit-code 1` are unchanged. Nothing about what is scanned or when the job fails moved.
- **Artifact named `gitleaks-report-nightly`**, not `gitleaks-report`. Learned on obsidian-vault#377: `upload-artifact` v4+ rejects a second upload under a name already used in one workflow run, and a caller could run more than one gitleaks job. Scoping the name per job removes that whole class of failure.
- **Verification:** step scripts extracted from the committed YAML and executed verbatim against gitleaks 8.24.3 (the version this job installs) in a scratch directory outside the repo, with synthetic non-functional values. Leak in window → exit 1; clean window → exit 0 with `[]`; `Secret`/`Match` recorded as `REDACTED` and the raw synthetic value grep-absent from the report; `File`/`StartLine`/`RuleID`/`Commit` present; summary renders under the pre-existing header. YAML parses.
- **Not executed:** behaviour on a real runner (`$GITHUB_STEP_SUMMARY`, artifact upload, the `steps.scan.outcome` gate) and `jq` presence on `ubuntu-latest`.
- **Commits/PRs:** this PR; related #23 and obsidian-vault#377.
- **Follow-up:** a red `Secret Scan` on `main` still alerts nowhere — unchanged and still separate from legibility.
