## 2026-09-07T00:25:00Z — Alerting when a scan goes red on a default branch (Claude Code)

- **Agent/tool:** Claude Code (remote session)
- **Repos:** dizhaky/.github; dizhaky/obsidian-vault (caller, separate PR)
- **Linear:** [Alert on a red Secret Scan](https://linear.app/dizhaky/project/alert-on-a-red-secret-scan-695ba0dc20dd) — DAN-3355 … DAN-3360
- **Why:** PRs #23, #24 and obsidian-vault#377 make a failed scan say *where* the finding is. None of them makes anyone *look*. `obsidian-vault` `main` sat red ~4.7h across five commits (`8e1bfe3472` 02:14Z → `b47ec713` 06:55Z) and was found only because a PR tripped over it.
- **Done:** `reusable-scan-failure-alert.yml` (`workflow_call`) opens a deduplicated issue when a scan concludes failure on the default branch, enriched with the redacted `file:line rule=…` locations pulled from the run's report artifact, and closes that issue on recovery. Slack is optional and fail-soft. Plus `repo-templates/secret-scan-alert.yml` (the `workflow_run` caller, which cannot live in the reusable workflow) and README rows.
- **Dedup is a label listing, not the search API.** Search is index-delayed, so two runs close together can both miss an issue that already exists. Listing by label is immediately consistent. Five red commits produce one issue plus four comments — that repetition going unnoticed is the original incident.
- **Slack is inert until configured, deliberately.** Neither repo defines any `SLACK_*` secret (the set in use is AUTO_MERGE_PAT, CODEX_WEBHOOK_SECRET, CODEX_WEBHOOK_URL, GH_PAT, GITHUB_TOKEN), and the nexus gateway's Slack grant is revoked (`account_inactive`). With no `SLACK_WEBHOOK_URL` the step logs two `::notice::` lines naming the secret and exits 0. **A notifier that dies silently is the exact defect this workflow exists to remove**, so the unconfigured case is loud rather than absent.
- **Verification — executed, not reasoned:** step scripts extracted from the committed YAML and run verbatim against a `gh` stub. No existing issue → creates; existing #42 → comments only, zero `issue create`; success + open alert → closes with the green run named. Artifact present / absent / `[]` all render correctly, including a path containing a space. Slack exercised against a real local HTTP sink: 200 → "Slack notified" with well-formed single-key JSON; unreachable → warning, exit 0; unset → notice, exit 0. YAML parses; all six `run` blocks pass `bash -n`. Repo test suite passes.

Both fixed and re-verified.
